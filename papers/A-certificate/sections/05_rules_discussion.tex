\section{Design rules}
\label{sec:rules}

\begin{enumerate}
\item \textbf{Audit before you optimize, in the deployment domain.}
A few dozen blind labels on separated axes, a decorrelated stratum, and partial correlations; registered categorical verdicts predicted all in-domain pressure outcomes per estimand (Section~\ref{sec:pressure}).
\item \textbf{Do not substitute raw agreement.}
It ranks but cannot diagnose, and it has no sign-anchored conviction (Table~\ref{tab:h2h}).
\item \textbf{Choose nuisance axes by threat model, and treat the audit as a screen for the axes it instruments.}
Style is the dominant documented axis and ours; length, format, and duplication were causally probed and cleared for these judges; position bias is measurable label-free by order-swap.
An axis orthogonal to all instrumented ones can evade the audit; the pressure test is the axis-agnostic backstop.
\item \textbf{Give a judge a reference only when the answer is unique and the judge can use it.}
On multi-valid tasks the lever inverts and amplifies gaming (Section~\ref{sec:audit}).
\item \textbf{Audit the oracle before the evaluator.}
Apparent evaluator failures in our own data dissolved, on adjudication, into evaluation-pipeline verdict errors~\cite{companionC}.
\end{enumerate}

\section{Discussion and limitations}
\label{sec:limits}

Six things bound the claim.
First, the labels: one annotator, an author, hypothesis-aware; a second rater and an external annotator are in progress, and every headline number is provisional until consensus labels land.
The style axis is the noisier instrument (cross-rater $0.52$, ceiling $\approx 0.72$), which attenuates exactly the partials that carry convictions; against that ceiling the measured convictions ($+0.51$, $+0.59$) are proportionally large.
The honest frontier judge's soundness partial ($+0.90$) sits at the single-rater ceiling ($\approx 0.89$), so it should be read as saturating what one rater's labels can measure, not as a claim about the remaining fraction.
Second, the weak-judge boundary: verdicts for judges near the pass line sit within CI overlap at these label counts; the subsampling analysis quantifies which verdicts are stable, and convictions are while boundaries are not.
Third, scope of validation: one audited domain; code is extrapolation; the capability-gate explanation of the one miss is post hoc until the registered code audit runs.
Fourth, the pressure test is selection, not training; the frontier failure mode is precisely where selection understates risk, and a DPO validation is registered.
Fifth, population shift and family confound: the audit labels come from seventeen models' solutions while the pressure pools come from one generator, and all open-weights judges share the generator's family, so self-preference could inflate blind-judge gaming; a cross-family generator run and a deployment-pool label set are registered (the labeling instrument exists).
Sixth, effective sample size: the ten audited configurations' verdicts are strongly collinear with one protocol bit, reference presence, and beyond it there are roughly three distinct verdict classes (blind-weak, referenced-pass, style-loaded).
The validation is therefore closer to three independent tests than eleven.
The registered DPO training run and the reward-model paraphrase-replicate protocol below are the two designed tests that break this collinearity.
The label count is what sufficed here, not a derived minimum.

\paragraph{Making inflation comparable for reward models.}
The inflation estimand requires that selection and reporting use independent score replicates, which a judge provides through rubric paraphrases and a single scoring function does not, so the reward-model row is marked n/c.
A paraphrase-replicate protocol closes the gap: score paraphrase-perturbed replicates of each candidate, use one replicate for selection and the other for reporting, so the winner's-curse cancellation matches the judge protocol.
Running it would put the trained reward model on the same inflation scale as the judges and is queued as a next step.
