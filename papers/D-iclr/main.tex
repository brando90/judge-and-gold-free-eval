\title{Reference Answers Mislead Fast LLM Judges\\When Many Answers Are Valid}

\author{Anonymous authors\\Paper under double-blind review}

\begin{document}
\maketitle

\begin{abstract}
LLM judges are often given a reference answer, because checking a candidate against a known-correct answer is easier than judging it from scratch.
That logic holds when a question has one correct answer.
When it has several, the reference is only one of them, and we find that judges grade agreement with it instead of correctness.
Holding a candidate's text fixed and swapping which valid answer serves as the reference moves the candidate's score by 2.5 to 6.3 points out of 10 for fast judges, those that score in one token or after a short explanation, including Claude Sonnet~5 and the standard MT-Bench prompt.
With the reference in its prompt, a frontier judge scores 83.3\% of correct answers that differ from it at 3/10 or below, against 20.5\% without it, and on tasks with several valid answers best-of-64 selection picks a correct answer 9 to 31 points less often for all five open judges we test.
These judges behave as if they run a cheap equality check: the effect survives spelling the reference out in words, mostly disappears when checking equality takes one arithmetic step, and shrinks when the answer is a program.
A judge that reasons at length before scoring behaves differently: with thinking enabled, Qwen3-8B checks each answer itself, and swapping the reference moves its scores by at most 0.011 points.
For fast judges, telling the judge that other answers count helps only some of them, while scoring blind first and then showing the reference together with the blind score keeps nearly all of the reference's benefit on unique-answer math problems (95.2\% selection accuracy against 98.1\%) and recovers part of the lost accuracy on multi-answer tasks.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Ask for any divisor of 91 strictly between 1 and 91.
Both 7 and 13 are correct.
Give an LLM judge the question, a candidate answer, and the reference answer 7, and it can do one of two things that look alike: check whether the candidate is right, or check whether it says 7.

We asked a frontier Claude Sonnet model, through Claude's command-line interface, to score correct answers on 37 questions that each have several valid answers.
Without a reference, it scored answers that happened to match the answer on file and answers that did not about the same, 7.9 and 7.8 out of 10.
With the reference in the prompt, matching answers rose to 9.8 and non-matching answers fell to 2.3 (\cref{fig:teaser}a).
Most of those correct, non-matching answers now received a failing score.

Reference-guided judging is standard practice.
MT-Bench's math and reasoning template tells the judge to begin ``by comparing the assistant's answer with the reference answer''~\citep{zheng2023judging}, references raise agreement with human labels~\citep{refguided2024}, judges without one are too generous~\citep{generous2026}, and a recent study of math grading found that comparing against a reference was the most reliable single-pass strategy~\citep{chen2026rethinking}.
The same judges choose among sampled answers and score rollouts for training, so whatever they reward is what gets optimized~\citep{gao2022scaling}.
The comparison is safe only when the reference is the only correct answer.
Curated math benchmarks mostly satisfy that, but other tasks do not: in an audit of 200 sampled questions each, 2.5\% of GSM8K and DeepScaleR problems and 30.0\% of NQ-open questions admitted more than one correct answer (\cref{app:prevalence}), and tasks that ask for an example, a construction, or a program admit many by design.

Prior work comes close to this failure without isolating it.
\citet{fixation2025} name it ``solution fixation'' but measure it by rewriting flawed solutions in the reference's style.
\citet{judgingref2026} and \citet{krumdick2025nofreelabels} replace the gold reference with an incorrect one, and work on verifier false negatives in reinforcement learning studies different surface forms of the same answer~\citep{xu2025tinyv,huang2025pitfalls}.
None of it varies which valid answer is the reference, and none asks what happens when something optimizes against such a judge.

We study both questions on tasks where a program decides validity, so we know every valid answer and can set how many there are.
We call a judge \emph{fast} if it scores in a single token or after a short explanation, as scalar judges, MT-Bench-style graders, and lightweight verifiers do, and contrast it with a judge that reasons at length before scoring.
Our findings, in the order of the paper:

\begin{itemize}[leftmargin=1.2em,itemsep=2pt,topsep=2pt]
\item \textbf{The score follows the reference} (\cref{sec:follows}). Swapping which valid answer is the reference, with the candidate's text unchanged, moves its score by 2.5 to 6.3 points, while answers that match neither reference barely move (\cref{fig:teaser}b). This holds for Claude Sonnet~5, under the MT-Bench template, and for answers the judge had already scored as correct without a reference. It disappears for a judge that thinks at length before scoring, which verifies each answer directly.
\item \textbf{Selection pays for it in accuracy} (\cref{sec:selection}). With the reference shown, best-of-64 picks a correct answer less often on multi-answer tasks for all five open judges on our $k$-pool, and the loss grows with the number of valid answers $k$. On unique-answer math problems the same reference raises accuracy by 27.6 to 43.8 points.
\item \textbf{Judges behave as if checking equality against a readable answer} (\cref{sec:mechanism}). The effect survives writing the reference in words, largely disappears when equality takes one arithmetic step or the answer is masked, and shrinks as the answer format moves from an integer to a program.
\item \textbf{A change of protocol helps more than a change of prompt} (\cref{sec:fix}). Instructions that other answers count help only some judges. Scoring blind first and then revealing the reference with the blind score keeps nearly all of the reference's benefit on unique answers and recovers part of the loss on multi-answer tasks.
\end{itemize}

We label evidence throughout as preregistered on OSF\osf, pre-specified in a timestamped commit before the data existed\pre, or post hoc\ph. \Cref{app:ledger} scores every prediction, including those that failed.

\section{Setup}
\label{sec:setup}

\paragraph{Tasks.}
Our own tasks come from five constraint families (remainder systems, subset sums, Goldbach pairs, divisor counts, digit sums), for example ``name two primes that sum to 100.''
Each task stores its full valid set $\mathcal{V}$ and one member $r \in \mathcal{V}$, drawn at random when the task is built, that serves as the reference.
A candidate is correct if and only if its answer is in $\mathcal{V}$.
The two main pools are a 120-task \emph{replication pool}\osf{} and a 75-task \emph{$k$-pool}\osf{} with exactly $k \in \{1,2,4,8,16\}$ valid answers per task, 15 tasks each.
We also use \textsc{MACE}~\citep{mace2026}, whose questions have 1, 2, 4, or 6 correct answers by construction, MBPP~\citep{austin2021mbpp} for code, and MATH-500~\citep{hendrycks2021math} for unique answers (\cref{app:setup}).

\paragraph{Candidates and judges.}
Llama-3.1-8B-Instruct writes 64 samples per task at temperature 1 (Qwen2.5-7B-Instruct for MATH-500 and MBPP).
Each sample is judged \emph{blind}, from the question and the candidate, and \emph{referenced}, with $r$ added under the heading ``Reference answer (trusted)''.
The main judges are Qwen2.5-7B-Instruct and phi-4; we also test the Qwen2.5 family from 1.5B to 14B, Llama-3.1-8B, gemma-2-9b, Mistral-7B, Claude Sonnet~5, and GPT-4.1.
Following common practice for scalar judging, our two paraphrased rubrics ask for a single integer from 0 to 10; the referenced version of rubric~$a$ asks the judge to rate correctness ``using the reference to check it,'' and rubric~$b$ to ``compare the candidate response against the trusted reference answer'' (full prompts in \cref{app:setup}).
Open judges report the expected score over the tokens 0 to 10.

\paragraph{Measurements.}
The \emph{anchoring margin} is the mean score of valid samples that match $r$ minus the mean score of valid samples that do not, on the 0 to 10 scale; a judge that grades correctness has a margin near zero.
\emph{Selection accuracy} is the share of tasks where the best-of-64 pick under rubric~$a$ is correct, averaging over ties.
The \emph{false-rejection rate} is the share of valid, non-matching samples scored 3 or below.
The preregistered endpoint of the OSF studies is \emph{inflation}: how far above an average answer of the same correctness the chosen answer scores, in pool standard deviations of the judge's rubric-$b$ scores (\cref{app:setup} gives the estimator).
We report referenced minus blind for each, per task, with task-level bootstrap intervals.

\section{Moving the reference moves the score}
\label{sec:follows}

If the reference were an answer key, a candidate's score could not depend on which of two valid answers sits in the reference slot, because the candidate is correct either way.
We kept the replication pool's samples byte-identical and re-judged them with the reference moved to another valid answer, the one that appears most often among each task's valid samples.

The score follows the reference (\cref{fig:teaser}b).
Text that now matches the reference gains 4.97 points under Qwen2.5-7B and 4.09 under phi-4, text that no longer matches loses $-5.04$ and $-3.92$, and valid text that matches neither moves by $+0.13$ and $+0.30$.
All twelve pre-specified cells hold (two judges, two rubrics, three predictions: a gain, a loss, and a gain larger than the change for text matching neither), and the second rubric gives larger gains for Qwen ($+6.34$) and smaller ones for phi-4 ($+3.25$).
Claude Sonnet~5, run through the same prompts with its scores read from a schema-checked tool call, shows the same pattern at $+3.04$ and $-2.66$.
Within the Qwen2.5 family on an exploratory pool, the 14B judge moves by about a third as much as the 1.5B judge ($+3.1$ against $+9.5$), and no judge we tested stops moving (\cref{app:rotation}).
Our rubrics ask for a bare integer, so we tested two judges that write before scoring (\cref{fig:teaser}b; \cref{app:rotation})\pre.
Under the verbatim MT-Bench reference-guided template, which asks for a short explanation (259 tokens on average with the reference) before the rating, Qwen2.5-7B's score rises by $+3.62$ when the reference moves onto a sample and falls by $-3.59$ when it moves off, while samples matching neither move by $+0.08$.
A judge that thinks at length does not show the effect.
With thinking enabled, Qwen3-8B writes 569 to 678 tokens per rotation judgment, and swapping the reference changes its scores by $-0.006$ for text that now matches and $+0.011$ for text that no longer matches.
It gives 10/10 to nearly every valid answer whether or not the reference agrees, while invalid answers average about 3, and most of its final explanations mention the reference before setting it aside.
On these tasks, which can be checked by calculation, extended reasoning replaces the equality check with verification; we have not tested tasks that are hard to verify, or frontier judges with extended thinking, since our Sonnet~5 runs had it disabled.

A charitable reading is that the judge did not know the other answer was correct and the reference informed it.
If so, answers the judge had already scored at 7 or above while blind should not move.
They move just as much: $+4.99$ for Qwen2.5-7B (91\% of samples kept), $+4.08$ for phi-4 (98\%), and $+2.79$ for Sonnet~5 (91\%).

The introduction's frontier numbers come from a separate pre-specified check through Claude's command-line interface, which returns sampled integer scores, on the 37 multi-answer tasks of the $k$-pool with matching and non-matching valid samples (660 calls).
Blind, it scored 20.5\% of correct non-matching answers at 3 or below; with the reference, 83.3\% \ci{75.5}{90.3}.
Because its scores are integers and tie heavily under best-of-64, we use this judge only for scores, not for selection.

\section{What best-of-$n$ selection loses}
\label{sec:selection}

\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{figures/fig2_selection.pdf}
\caption{\textbf{Showing the reference costs accuracy when several answers are valid.}
\textbf{(a)}~Change in the accuracy of the best-of-64 pick when the reference is shown, on the $k$-pool: tasks with a unique answer (hollow) and with several valid answers (filled). Task-level 95\% intervals.\ph{}
\textbf{(b)}~Share of correct answers that differ from the reference that are scored 3 or below, blind (orange) and with the reference (blue). The first three judges are on the replication pool; the Claude CLI judge is on 37 $k$-pool tasks.\ph}
\label{fig:selection}
\end{figure}

\paragraph{The preregistered replication.}
The replication pool was built to test whether the reference raises inflation under best-of-64 selection, with population, estimator, and endpoints fixed before any generation.
It does: the reference adds $+1.19$\sd \ci{+1.02}{+1.36} of inflation over blind judging, and both judges' intervals exclude zero\osf.
Selection collapses onto the reference.
On the 93 tasks with both matching and non-matching valid samples, the referenced judge picked a matching answer where the blind judge did not on 56 tasks for Qwen2.5-7B and 76 for phi-4, against 2 and 0 the other way\osf.
In plain accuracy, phi-4's pick is correct 86.7\% of the time with the reference and 98.1\% without; Qwen2.5-7B's drop, from 76.2\% to 68.6\%, has an interval that includes zero\ph.
The false-rejection rate shows the mechanism behind the drop: correct answers that differ from the reference are scored 3 or below 28.0\% of the time by Qwen2.5-7B with the reference and 0.4\% blind, 5.8\% and 0.03\% by phi-4, and 26.2\% and 4.9\% by Sonnet~5 (\cref{fig:selection}b)\ph.

\paragraph{The effect of $k$.}
When a question has exactly one valid answer, matching the reference and being correct are the same event, so a judge that anchors cannot be misled by the reference.
The question is how much it costs once $k$ exceeds one.
On the $k$-pool, showing the reference lowers selection accuracy at $k{>}1$ for all five open judges we ran there, by 9 points (Mistral-7B) to 31 points (Qwen2.5-7B), and every interval excludes zero (\cref{fig:selection}a)\ph.
The loss grows with $k$: at $k{=}2$ no judge's loss is distinguishable from zero, while at $k{=}16$ the pick is correct 71.4 and 85.7 points less often for Qwen2.5-7B and phi-4 (7 tasks; \cref{app:grid}).
At $k{=}1$ the reference leaves accuracy unchanged for phi-4, Qwen2.5-14B, and gemma-2-9b; Qwen2.5-7B and Mistral-7B lose accuracy even there, which we trace to incorrect answers that resemble the reference (\cref{app:composition}).
The preregistered inflation endpoint agrees: the step from $k{=}1$ to $k{>}1$ is $+1.45$ and $+1.18$\osf, it is positive for all six judges on a separate synthetic grid\pre, and it appears on the audited domains of the third-party \textsc{MACE} benchmark ($+2.30$ and $+1.13$; \cref{app:mace})\pre.
The MT-Bench template shows the same pattern in accuracy: on a 16-sample subsample of the $k$-pool, showing the reference raises best-of-16 accuracy by 16.6 points at $k{=}1$ (interval including zero) and lowers it by 13.0 points at $k{>}1$\pre. The thinking judge's accuracy changes by $-5.8$ and $-3.7$ points on the same subsample.

\paragraph{Unique answers.}
On 105 MATH-500 problems, where every problem has one answer, the same reference raises selection accuracy by 27.6 to 43.8 points for all four Qwen2.5 judge sizes (for Qwen2.5-7B, from 67.6\% to 98.1\%; \cref{app:ties})\ph.
The reference is a strong tool exactly where it is an answer key.

\paragraph{Training.}
A policy trained with DPO on pairs labeled by the referenced Qwen2.5-7B judge raised that judge's score by 1.76 points while its accuracy on training tasks fell from 41.2\% to 17.5\%. Every control arm we trained failed its own manipulation check, so we cannot attribute this to the reference rather than to generic overoptimization; \cref{app:dpo} gives the details.

\section{What the judge is checking}
\label{sec:mechanism}

\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{figures/fig3_mechanism.pdf}
\caption{\textbf{Judges behave as if comparing a readable answer, and the harm shrinks as that comparison gets harder.}
\textbf{(a)}~Anchoring margin when the reference is written as a numeral, in words, or as an expression (replication pool, 93 tasks), and when a worked solution is shown with its final answer visible or masked (21 $k$-pool tasks with a single-number answer). Rubric~$a$.\pre{}
\textbf{(b)}~Added inflation when the same content is requested as an integer, a pair, a JSON object, or a Python program whose output is checked (25 new tasks).\pre}
\label{fig:mechanism}
\end{figure}

A cheap way to use a reference is to extract the candidate's final answer and check whether it equals the reference's.
Three pre-specified rewrites of the reference test whether judges behave this way (\cref{fig:mechanism}a).
Writing 31 as ``thirty-one'' leaves phi-4's margin essentially unchanged ($+3.68$ against $+3.79$) and keeps about two-thirds of Qwen2.5-7B's ($+2.88$ against $+4.62$), although the reference then shares no characters with a numeric answer.
Writing it as ``30+1'' shrinks the margins to $+0.29$ and $+0.89$.
A worked solution with its final answer visible anchors strongly ($+2.97$ and $+3.51$), and the same solution with every occurrence of the final answer masked does not ($+0.05$ and $-0.49$).
Sonnet~5 behaves the same way on the first two rewrites (\cref{app:mechanism}).
Among non-matching correct answers, the penalty does not shrink as the answer gets numerically closer to the reference; only exact equality matters (\cref{app:composition}).
We read this as a semantic equality check on a readable answer.
A follow-up that encoded the reference with an explicit decoding rule removed the margin after a single step, but its prompt announced the encoding, which may explain the collapse by itself (\cref{app:mechanism}).

If the check needs a readable answer, it should weaken when the answer is an artifact.
An earlier pre-specified prediction that a canonical MBPP solution would anchor like a short answer failed: on the 58 tasks shared across conditions it lowered inflation relative to blind judging instead (\cref{app:code}).
We then tested the idea on 25 new tasks, each requested in four formats with the content held fixed (\cref{fig:mechanism}b).
Added inflation fell from $+1.66$ for integers to $+0.13$ for programs under Qwen2.5-7B, and from $+1.35$ to $-0.37$ under phi-4\pre.
Our prediction that the harm would vanish at the program format held for phi-4 and failed for Qwen2.5-7B; phi-4's program result also depends on a checker bug we fixed after registration, and under the original labels it is null (\cref{app:code}).

\section{What to do about it}
\label{sec:fix}

\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{figures/fig4_fix.pdf}
\caption{\textbf{Blind-then-reveal keeps the reference's benefit on unique answers and recovers part of its cost on multi-answer tasks.}
\textbf{(a)}~Change in selection accuracy relative to blind judging (orange line at zero) on the $k$-pool at $k{>}1$, with the reference shown (blue) and with blind-then-reveal (teal); arrows run from one to the other. 39 tasks, 95\% intervals.\ph{}
\textbf{(b)}~Selection accuracy on 105 unique-answer MATH-500 problems for the three protocols, best of 64.\pre}
\label{fig:fix}
\end{figure}

\paragraph{Let the judge verify.}
The most direct fix is a judge that reasons before scoring: on our tasks the thinking judge was not moved by the reference (\cref{sec:follows}), at a cost of 569 to 1,092 generated tokens per candidate instead of one. The remaining options matter when that cost is too high, as it is for scoring rollouts at scale, or when a task is too hard for the judge to verify.

\paragraph{Prompts help only some judges.}
Adding ``the reference shown is one valid answer among possibly many \ldots\ any correct answer deserves full credit'' removes phi-4's margin on the synthetic grid at $k{=}16$ ($+1.91$ to $+0.03$, 4 to 6 tasks per cell) and shrinks Qwen2.5-14B's ($+3.34$ to $+1.21$), but does not help the smaller judges\pre.
A second wording that tells the judge not to compare against the reference at all gives the same ordering of judges.
On Sonnet~5 the two wordings shrink the margin from $+3.00$ to $+2.08$ and $+2.60$, and on GPT-4.1 from $+0.99$ to $+0.46$ and $+0.59$; neither removes it\pre.
A worked solution in place of a bare answer anchors less but still adds inflation ($+1.08$ and $+0.77$; \cref{app:mitigation}).

\paragraph{Blind, then reveal.}
The protocol we preregistered as the main mitigation uses two calls.
The first scores the candidate blind.
The second shows the reference together with that blind score and states that a correct answer differing from the reference keeps its score.
On the $k$-pool it removes the preregistered inflation at $k{>}1$ ($-0.05$ and $+0.16$, against $+1.50$ and $+1.07$ with the reference alone)\osf.
In accuracy it recovers part of the loss (\cref{fig:fix}a)\ph: 20.5 points of the 30.8 lost by Qwen2.5-7B, and the entire loss for Qwen2.5-14B and Mistral-7B, but only 5.1 of 20.5 points for phi-4 and 5.1 of 17.9 for gemma-2-9b.
On unique-answer MATH-500 problems, where the reference helps, the protocol keeps nearly all of that help (\cref{fig:fix}b)\pre: Qwen2.5-7B's pick is correct 95.2\% of the time, against 98.1\% with the reference and 67.6\% blind, and Qwen2.5-14B's 93.5\%, against 95.2\% and 67.6\%.
We had predicted it would keep less than half, because of the result below; that prediction failed for both judges.

\paragraph{Why it works.}
A pre-specified decomposition on the $k$-pool finds that the displayed number carries the protection.
Removing the blind score from the second call, while keeping the reference and the instruction, brings the inflation back ($+1.42$ and $+0.36$)\pre.
Showing another judge's blind score instead protects phi-4 as well as its own; for Qwen2.5-7B it leaves $+0.38$ of inflation against $+0.01$, and gemma-2-9b also protects itself less with another judge's score (\cref{app:mitigation}).
This fits evidence that judges anchor on previously displayed scores~\citep{kapetanovic2026anchoring}: the reveal call replaces the reference as the anchor with a number that already encodes a correctness judgment, and the reference then matters mostly where that judgment was wrong.
In accuracy units the variant contrasts are noisier than in inflation, and only Qwen2.5-7B shows the no-score arm clearly worse than the standard arm (\cref{app:mitigation}).

\section{Related work}
\label{sec:related}

\paragraph{Reference-guided judging.}
References are the standard remedy for grading math and reasoning with LLM judges~\citep{zheng2023judging,refguided2024,chen2026rethinking}, and judges without them over-credit wrong answers~\citep{generous2026}.
Judges also depend on the reference being correct: replacing it with a wrong answer collapses their accuracy~\citep{judgingref2026}, and without a correct reference they agree with experts mainly on questions they can answer themselves~\citep{krumdick2025nofreelabels}.
\citet{fixation2025} describe a bias toward the reference's solution method, measured with flawed solutions rewritten in the reference's style.
We keep the reference correct and vary which valid answer it is.
Generating a reference before judging has been proposed as an improvement~\citep{dobefore2025}; our account predicts that a self-generated reference anchors the same way on multi-answer tasks, which we have not tested.

\paragraph{Verifiers and many valid answers.}
Rule-based and model-based verifiers in reinforcement learning miss correct answers written in a different form~\citep{xu2025tinyv,huang2025pitfalls,chen2025xverify}, which is a question of equivalence between surface forms of one answer.
Our setting is answers that are genuinely different.
RL data pipelines often avoid it by keeping only problems that ``admit a single correct answer''~\citep{albalak2025bigmath}.
Single-reference evaluation is known to undercount correct outputs when questions admit several~\citep{min2020ambigqa}, and \textsc{RewardBench-2} and \textsc{MACE} build benchmarks around such questions~\citep{malik2025rewardbench2,mace2026}.

\paragraph{Judge biases and optimization.}
LLM judges favor the first response~\citep{wang2024fair}, longer responses~\citep{dubois2024lengthcontrolled}, and their own outputs~\citep{panickssery2024llm}; they anchor on scores shown to them~\citep{kapetanovic2026anchoring}; and they can be fooled by content-free responses~\citep{zhao2025onetoken}.
Optimizing against an imperfect evaluator inflates its scores~\citep{gao2022scaling,rafailov2024scaling}, and good average agreement does not guarantee good best-of-$n$ choices~\citep{landesberg2026bestofn}.
Closest to our protocol, a reference-free judge that commits to its own answer before seeing the candidate resists self-play reward hacking~\citep{zhou2026convincing}; blind-then-reveal applies the same idea of committing first to reference-guided judging.

\section{Limitations}
\label{sec:limits}

\begin{itemize}[leftmargin=1.2em,itemsep=1pt,topsep=2pt]
\item \textbf{Tasks.} Our positive results come from constraint problems and short factual questions where validity is decided by a program or, for \textsc{MACE}, by an audited answer list. We do not test free-form generation, long references, contested validity, or step-level verifiers.
\item \textbf{Judging protocol.} Most results use one score token under our rubrics, and rubric~$b$ tells the judge to compare against the reference. The MT-Bench template reproduces the rotation and $k$ results for one judge on subsamples. One 8B thinking judge showed no anchoring on tasks that can be verified by calculation; we did not test thinking judges on hard-to-verify tasks, other thinking models, or frontier judges with extended thinking (Sonnet~5 ran with it disabled).
\item \textbf{Generators and judges.} Most pools use one 8B generator. Open judges are 14B parameters or smaller; Sonnet~5 is the only frontier judge with rotation and masking results, and GPT-4.1's $k$ step is unresolved because its scores tie heavily (\cref{app:frontier}).
\item \textbf{Sample sizes.} The $k$-pool has 14 tasks at $k{=}1$ and 7 at $k{=}16$ after filtering; the synthetic grid has 4 to 6 tasks per cell. We rely on patterns that repeat across pools.
\item \textbf{Units and registration.} Accuracy and false-rejection readouts are post hoc; the registered endpoints are inflation. Three experiments have third-party timestamps and the rest rely on git commits. One registered confirmation (blind-then-reveal lowering inflation for Mistral-7B) varies across reruns of its analysis (\cref{app:ledger}).
\item \textbf{Mitigation.} Blind-then-reveal was tested on the $k$-pool and on MATH-500 with open judges, not with frontier judges or trained policies; whether it protects a trained policy is open.
\end{itemize}

\section{Conclusion}
\label{sec:conclusion}

A reference answer is a good check when a question has one right answer.
When it has several, the reference is one of them, and judges grade agreement with it: moving the reference moves the score of unchanged text, correct answers that differ from it are marked as failing, and best-of-$n$ selection picks them less often.
Fast judges behave as if checking a readable answer for equality, so the harm is largest for short answers and fades for programs, and a judge that reasons at length verifies the answer instead.
Asking the judge to accept other answers is not reliable.
Scoring blind first and revealing the reference with the blind score keeps most of what the reference is good for, and when validity can be checked by a program, that check is better than any judge.

\subsection*{AI use statement}
In this work, generative AI models were the experimental subjects: open and frontier LLMs generated candidate answers and served as the judges under study (\cref{sec:setup}, \cref{app:setup}). One pilot (\cref{app:mathconstraint}) used a Claude model to generate candidate solutions, each verified by exact programmatic checks. We used generative AI tools to help write analysis code, draft and edit text, produce figures, search and verify related work, and label a sample of dataset questions for the prevalence audit, whose labels were double-coded and adjudicated. We did not use generative AI tools to choose the scientific claims without verification: every number in the paper is produced by committed analysis scripts from stored model outputs, and we checked every claim against those outputs. We take responsibility for the final content of this work, including text, claims, and artifacts produced with the aid of generative AI.

\subsection*{Ethics statement}
This work studies a failure of automated evaluation that can make optimized models look better than they are. We release no new model and no attack on a deployed system. Anyone optimizing against a reference-guided judge on multi-answer tasks can exploit the failure, which is why we pair it with a mitigation and recommend verifying judges on the tasks where they are used. No human subjects were involved.
